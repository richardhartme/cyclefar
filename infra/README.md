# CycleFar AWS infrastructure

For an AWS-native alternative, see the [CloudFormation template and deployment guide](cloudformation/README.md). Choose one tool to manage an environment; do not deploy both configurations for the same application.

This directory contains the initial Terraform configuration for a small, single-server CycleFar production deployment. Terraform provisions AWS infrastructure only; it does not build or deploy the Rails application.

## What it creates

- one VPC;
- one public application subnet with an Internet Gateway and public route;
- two private database subnets in separate Availability Zones, required by the RDS DB subnet group;
- one Ubuntu 24.04 LTS EC2 instance with an Elastic IP, SSH access and an SSM-enabled IAM instance profile;
- application and database security groups;
- one encrypted PostgreSQL RDS instance with seven days of automated backups;
- an optional Route 53 `A` record for `cyclefar.com` in an existing hosted zone.

The database is not publicly accessible. Its security group accepts PostgreSQL on port 5432 only from the EC2 application security group. The private database subnets do not have a NAT gateway or an Internet route.

This intentionally does not create ECS, Kubernetes, load balancers, autoscaling, Redis, CloudFront, NAT gateways, or deployment resources.

## Prerequisites

- Terraform 1.6 or newer (but below Terraform 2.0);
- an AWS account and an AWS IAM identity permitted to manage VPC, EC2, Elastic IP, IAM instance profiles, RDS and, when used, Route 53 records;
- an SSH key pair, supplied either as an existing EC2 key-pair name or an OpenSSH public key;
- an existing Route 53 hosted zone only if Terraform should create the `cyclefar.com` record.

AWS credentials are resolved by the normal AWS provider chain. For example, configure an AWS CLI profile and authenticate with SSO:

```sh
aws configure sso --profile cyclefar
aws sso login --profile cyclefar
export AWS_PROFILE=cyclefar
aws sts get-caller-identity
```

Environment credentials or an assumed role work too. Do not put AWS access keys in Terraform files.

## Configure variables

Copy the safe example and replace its placeholders:

```sh
cd infra
cp terraform.tfvars.example terraform.tfvars
```

`terraform.tfvars` is ignored by Git. Set exactly one of `ssh_key_name` or `ssh_public_key`, and set `ssh_allowed_cidrs` to your trusted public IP range before a real apply. Terraform rejects an empty SSH CIDR list.

The RDS password is generated by the `random_password` provider when `database_password` is left `null`. Terraform marks its output as sensitive, but it is still stored in Terraform state. Keep state out of Git and protect it. To supply a password from a secure local shell instead, use:

```sh
export TF_VAR_database_password='a-secret-not-committed-to-git'
```

RDS initial database names cannot contain underscores, so the default is `cyclefarproduction`. Before deploying Rails, configure its primary, cache, queue and cable database names to match the RDS instance or create the required databases with the RDS master user. This infrastructure change deliberately does not alter Rails or Kamal configuration.

`route53_zone_id` is optional. Terraform does not create or discover a hosted zone. When it is set to an existing zone ID, Terraform creates an `A` record for `domain_name` pointing at the application Elastic IP. Ensure `cyclefar.com` is registered and delegated to that hosted zone first.

## Terraform workflow

Run these commands from `infra/`:

```sh
terraform init
terraform fmt
terraform fmt -check
terraform validate
terraform plan
```

Review the plan carefully. A later manual apply is deliberately explicit:

```sh
terraform apply
```

No apply command is run by this repository or by Terraform configuration. To remove the resources later, review the destructive plan and run:

```sh
terraform destroy
```

By default, destruction creates a final RDS snapshot. It may take time and continues to incur snapshot storage cost. Set `rds_skip_final_snapshot = true` only when discarding the database intentionally.

## Costs

The main AWS costs are the EC2 instance and EBS volume, Elastic IP when it is not attached to a running instance, RDS instance and storage, RDS backup/snapshot storage beyond included allowances, Route 53 hosted-zone/query charges, and outbound data transfer. The defaults (`t3a.small`, `db.t4g.micro`, 20 GiB RDS storage) target a very low-traffic personal application; check current regional AWS pricing before applying.

## Later Kamal connection

Kamal remains unconfigured. After provisioning, use these outputs to prepare it manually:

```sh
terraform output application_server_public_ip
terraform output database_endpoint
terraform output database_username
terraform output -raw database_password
```

The EC2 Elastic IP will become Kamal's web host. The RDS values will later be supplied to the container as `DB_HOST`, `DB_PORT`, `DB_USERNAME` and `DB_PASSWORD`; `RAILS_MASTER_KEY` remains a separate Kamal secret. Configure Docker, Kamal's registry, the production hostname, TLS and Rails force-SSL settings in a later change rather than through this Terraform configuration.
