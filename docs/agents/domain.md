# Domain docs

This is a single-context repository. Engineering skills should use `GLOSSARY.md` at the repository root for domain terms and `docs/adr/` for architecture decisions.

Before exploring an area, read the glossary and relevant ADRs if they exist. Their absence needs no action; create them when domain terms or decisions are resolved. Use glossary terms in issues, proposals, and tests. Surface any conflict with an ADR explicitly.

The product and training specifications named in `AGENTS.md` remain authoritative under its stated precedence.
